# KernSigner Complete Feature Operations Manual

Date: 2026-05-21

This manual organizes KernSigner's current main features into an entry map by "What I Want to Do." It is NOT a commercial production commitment; the current firmware is still used as a test fund acceptance version.

If you're using KernSigner for the first time, first read [小白照抄完整使用手册.md](小白照抄完整使用手册.zh-CN.md) or [零基础第一次上手教程.md](零基础第一次上手教程.zh-CN.md), then come back to this manual.

If you want to check features item-by-item by screen buttons, see [功能菜单逐项索引.md](功能菜单逐项索引.zh-CN.md). If you already have problems, see [故障排查照抄手册.md](故障排查照抄手册.zh-CN.md).

## General Principles

- Use test mnemonics and test funds first.
- Backup and recovery drills before receiving funds.
- Before signing, you MUST verify addresses, amounts, chains, fees, contracts, and authorizations on KernSigner.
- If you don't understand, cancel; do NOT sign just to complete a flow.
- Smart card write-card, PIN change, reset, and SeedKeeper management have entered the test card acceptance scope, but cannot be advertised as audited production capabilities; Satochip BTC PSBT card signing etc. have not completed production acceptance.

## Mnemonic Creation

Supported creation methods include:

| Method | Suitable Scenario |
| --- | --- |
| `Hex` | Precise verification with BIP39 tools |
| Coin Flip | Using physical randomness 0/1 |
| Dice | Using six-sided dice |
| D20 | Using twenty-sided dice |
| Playing Cards | Using shuffled card order |
| Camera | Extracting random entropy from camera images |
| Manual | Entering existing BIP39 words |
| Smart Card | Using card-related randomness or account capabilities |

Each method must confirm the final mnemonic passes BIP39 validation. For detailed steps, see [MNEMONIC_CREATION_BIP39_VERIFY.md](MNEMONIC_CREATION_BIP39_VERIFY.zh-CN.md).

## Mnemonic Import

Common import methods:

- Manual entry of BIP39 words.
- Scan SeedQR or supported mnemonic QR codes.
- Enter BIP39 word indices.
- Restore from steel plate, 1248, dot matrix, Tinyseed, Stackbit.
- Load from smart card or SeedKeeper class flows.

After import, you MUST verify:

- Wallet fingerprint.
- First receiving address.
- Extended public key.
- Network and derivation path.
- Whether a passphrase is used.

## Backup and Recovery

Recommended minimum flow:

1. Plain text paper backup.
2. Offline BIP39 verification.
3. Clear session, then manually restore once.
4. Verify fingerprint and address.
5. Then consider metal backup, QR code backup, KEF encrypted backup, or smart card backup.

For complete details, see [BACKUP_AND_RECOVERY_GUIDE.md](BACKUP_AND_RECOVERY_GUIDE.zh-CN.md).

## Addresses and Extended Public Keys

KernSigner can display common BTC address types, extended public keys, and custom path addresses.

Verification focus:

| Item | Common Differences |
| --- | --- |
| Network | Mainnet and testnet differ |
| Address Type | Legacy, Nested SegWit, Native SegWit, Taproot differ |
| Derivation Path | `m/84'/0'/0'` and `m/49'/0'/0'` differ |
| Passphrase | With or without passphrase produces completely different wallets |
| Account Number | account 0 and account 1 differ |

If your phone wallet address does NOT match KernSigner's address, do NOT receive funds.

## BTC Watch Wallet and PSBT

Recommended BTC flow:

1. KernSigner displays xpub/ypub/zpub.
2. Phone or computer wallet imports watch account.
3. Watch wallet generates receiving address.
4. KernSigner verifies the address.
5. Watch wallet generates PSBT.
6. KernSigner scans, verifies, and signs.
7. Watch wallet scans back signed result and broadcasts.

Before PSBT signing, you MUST confirm:

- Inputs belong to current wallet.
- Recipient address is correct.
- Change address is correct.
- Fees are reasonable.
- Network is consistent.

## Web3 Wallet Connection and Signing

Current Connect Wallet entries target OKX, Bitget, imToken, MetaMask, Rabby, TokenPocket, and other Web3 wallet scenarios. These Web3 wallets have completed connection, QR code signing, and signed result back acceptance with test funds; BTC side BlueWallet and Electrum watch wallet/PSBT signing flows have also been tested in practice.

Common flow:

1. KernSigner generates connection QR code.
2. Phone wallet scans according to hardware wallet or Keystone compatible flow.
3. Phone wallet initiates a test transaction.
4. KernSigner scans the request and verifies the summary.
5. Sign using local mnemonic or Satochip smart card; SeedKeeper primarily stores secrets, and after importing to local, signs as `Mnemonic` source.
6. Phone wallet scans back the signed result.

If QR codes are too dense, before your first signature, first confirm the ESP32-P4 4.3 OV5647 camera has been focused with a standard QR code: keep at 10-20 cm, gently rotate the outer ring of the lens until clearest. If still difficult to scan, screenshot or cast to computer to enlarge for KernSigner to scan directly. For QR and OKX dot dynamic code troubleshooting, see [QR_CAMERA_TROUBLESHOOTING.md](QR_CAMERA_TROUBLESHOOTING.zh-CN.md).

TypedData/EIP-712 capabilities that are explicitly rejected or hidden on the page represent current security boundaries, NOT regular faults.
