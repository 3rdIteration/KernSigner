# KernSigner Complete Beginner's Step-by-Step Manual

Date: 2026-05-22

This manual is for anyone who receives a KernSigner firmware board for the first time. Think of it as your "follow-the-screen-taps" master guide: complete the initial flash, boot, security initialization, test mnemonic creation, backup, wallet connection, QR signing in order, then check smart card operations, direct QR scanning troubleshooting, and production boundaries as needed.

**Current firmware is a test fund acceptance version.** Do not import real mnemonic phrases, store real assets, or advertise this as an audited production wallet until you have completed the commercial release gate, device acceptance testing, and independent security audit.

## 0. Read This First

The KernSigner development board handles offline key storage or temporary key loading, address display, and QR code signing; your phone or computer wallet only handles network connectivity for balance checking, transaction construction, and broadcasting; private keys, mnemonic phrases, smart card PINs should NEVER enter your phone wallet, browser extensions, internet-connected web pages, or chat applications.

## 1. What You Need

| Item | Purpose | Beginner Notes |
| --- | --- | --- |
| Waveshare ESP32-P4-WiFi6-Touch-LCD-4.3 | Runs KernSigner firmware | Only `wave_43` 4.3" board is supported |
| USB data cable | Power, flashing, serial logs | Flashing uses USB-to-UART/download port |
| OV5647 camera | QR scanning, camera entropy | Manual focus adjustment required on first use; no camera = no QR scanning |
| Paper and pen | Write mnemonics, PINs, acceptance info | Record mnemonics and PIN/PUK separately in different locations; no photos, no cloud storage |
| Phone or computer wallet | Import watch-only wallets, initiate transactions | Do NOT import KernSigner mnemonics into this |
| Optional: Satochip/SeedKeeper | Smart card signing or secret storage | Requires powered OTG/Hub |
| Optional: Computer to zoom QR codes | Enlarge dense/small QR codes for display | For display assistance only; do not store sensitive materials |

## 2. Know Your Ports

Use only as follows:

```text
USB-to-UART / Download port -> Connect to computer for flashing and serial logs
USB OTG port -> Connect peripherals for powered Hub, card reader, smart cards
Camera -> QR scanning and camera random entropy
Touch screen -> All daily operations
```

Do NOT do this:

- Do not plug a smart card reader into the download port.
- Do not use an unpowered OTG cable to directly drive ACR39U-NF card reader.
- Do not treat other Waveshare screen boards as supported hardware.
- If using the repository's 3D printed case mockup, note that it currently blocks the TF/SD card slot and side buttons (POWER/BOOT/RESET).

Correct smart card connection:

```text
ESP32-P4 OTG port
-> Powered OTG adapter / truly externally powered Hub
-> ACR39U-NF card reader
-> Satochip or SeedKeeper smart card
```

## 3. Download and Flash Firmware

If you already have a board with firmware installed, skip to "First Boot." If you need to flash firmware yourself, follow below.

### 3.1 Choose the Right Firmware

| Situation | Which File | Address |
| --- | --- | --- |
| New board, blank board, unknown state board | `kernsigner-wave43-0.0.7-rc1-untested-full.bin` | `0x0` |
| Already running this project, only upgrade app | `kernsigner-wave43-0.0.7-rc1-untested-app.bin` | `0x20000` |

Firmware directory:

```text
firmware/wave_43/
```

### 3.2 Verify Firmware Integrity

Linux/macOS:

```bash
cd firmware/wave_43
sha256sum -c SHA256SUMS.txt
```

Windows PowerShell:

```powershell
cd firmware\wave_43
Get-FileHash .\kernsigner-wave43-0.0.7-rc1-untested-full.bin -Algorithm SHA256
```

If verification fails, STOP. Do not flash. Re-download or re-copy the firmware.

On Windows, compare the hash from `Get-FileHash` character-by-character with the corresponding entry in `SHA256SUMS.txt`. If even one character differs, do NOT flash.

### 3.3 Linux One-Click Full Firmware Flash

Connect the board's download port to your computer first. Assuming serial port is `/dev/ttyACM0`:

```bash
cd firmware/wave_43
./flash_wave43_linux.sh /dev/ttyACM0
```

If the serial port is not `/dev/ttyACM0`, check first:

```bash
ls /dev/ttyACM*
ls /dev/ttyUSB*
```

### 3.4 Windows One-Click Full Firmware Flash

First check the serial port in Device Manager, e.g., `COM3`, then run:

```bat
cd firmware\wave_43
flash_wave43_windows.bat COM3
```

Replace `COM3` with your actual serial port.

### 3.5 Post-Flash Minimum Checks

1. Device auto-restarts or manually restart.
2. Screen lights up.
3. Touchscreen responds.
4. Can enter PIN setup or home page.
5. Can access `Self-Test -> System` or `Self-Test -> Peripherals`.
6. Can open camera or QR scanner page.
7. Check camera focus with a standard QR code; if not responsive, gently rotate the outer ring of the lens until QR code edges appear sharpest.
8. If connected to smart card, use powered OTG first, then go to `Self-Test -> Smart Card`.

If you get black screen, garbled display, inaccurate touch, or won't boot, see [故障排查照抄手册](故障排查照抄手册.zh-CN.md) (troubleshooting guide).

## 4. First Boot and Device PIN

The device PIN is KernSigner's own PIN. It is NOT the smart card PIN.

First boot:

1. Plug USB to power the board.
2. Wait for screen to light up.
3. If you see `Set PIN`, enter a new device PIN.
4. PIN should be at least 6 digits; do not use `123456`, birthdays, or phone numbers.
5. If you see `Enter PIN`, enter your device PIN.
6. Once on the home page, do NOT rush to import real wallets. Complete test flows first.

PIN identification cheat sheet:

| Screen Text | What to Enter |
| --- | --- |
| `Set PIN` | New device PIN |
| `Enter PIN` | Device PIN |
| `Smart Card PIN` | Satochip or SeedKeeper card PIN |
| `PUK` | Smart card PUK |

If unsure, go back to previous page. Do NOT guess. The device PIN will clear the current session and shut down/reboot after 3 consecutive wrong attempts; smart card PIN/PUK wrong attempts consume the card's own remaining attempts.

For complete PIN details, see [SECURITY_PIN_GUIDE.md](SECURITY_PIN_GUIDE.md).

## 6. Creating a Test Mnemonic Phrase

Use only test mnemonics for your first practice.

Path:

```text
Home -> Mnemonic -> Create
```

Creation methods:

| Method | Suitable For | How-To |
| --- | --- | --- |
| `Hex` | Easiest to verify | 12-word: enter 32 hex chars; 24-word: enter 64 |
| Dice / `骰子` | Have a six-sided die | Enter `1-6` each roll |
| Coin Flip / `抛硬币` | Have coins | Heads=`1`, Tails=`0`, be consistent throughout |
| D20 | Have a twenty-sided die | Enter `1-20` each roll |
| Playing Cards / `扑克牌` | Have physical cards | Shuffle and enter card faces like `AH QS 9D TC` |
| Manual / `手动` | Already have test words | Enter BIP39 English words |
| Camera / `相机` | Quick entropy gathering | Photograph complex images |
| Smart Card / `智能卡` | Using SeedKeeper randomness | Connect powered OTG and card first |

Simplest test vector:

```text
00000000000000000000000000000000
```

Expected 12 words:

```text
abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about
```

This is a PUBLIC test mnemonic. NEVER use it for real assets.

For detailed verification, see [MNEMONIC_CREATION_BIP39_VERIFY.md](MNEMONIC_CREATION_BIP39_VERIFY.zh-CN.md).

## 7. Importing an Existing Mnemonic Phrase

Path:

```text
Home -> Mnemonic -> Import
```

Import methods:

| Method | Purpose | Notes |
| --- | --- | --- |
| `QR Code` | Scan SeedQR, Compact SeedQR, or supported mnemonic QR | QR code = mnemonic phrase |
| `Manual` | Enter 12/15/18/21/24 English words | Words and order must be exact |
| `Index` | Enter BIP39 numbers | Watch for numbering conventions |
| `Smart Card` | Import from SeedKeeper | Enter smart card PIN |
| `Storage Card` | Import from SD/file | Depends on hardware and case availability |
| `Encrypted` | Import KEF encrypted backup | Lost password = unrecoverable |
| `Steel Plate` | Restore from steel plate serial numbers | Verify fingerprint after restore |
| `Dot Matrix` | Tinyseed/1248/Stackbit class restore | Watch each dot position per word |

After successful import, you MUST verify:

1. Wallet fingerprint.
2. First receiving address.
3. Extended public key.
4. Network: mainnet or testnet.
5. Derivation path.
6. Whether BIP39 passphrase is used.

"Import Successful" alone is not enough. Stop if addresses don't match.

## 8. Backup and Recovery Drill

After creating or importing a mnemonic, backup first, then receive funds.

Common paths:

```text
Home -> Mnemonic -> Local Mnemonic -> Backup
```

Or from the loaded wallet menu:

```text
Local Mnemonic -> Backup
```

Recommended minimum backup for beginners:

1. Open plain text mnemonic or index page.
2. Write down words and indices in order on paper.
3. Verify each word after writing.
4. Clear session.
5. Re-import via `Import -> Manual`.
6. Verify wallet fingerprint and first address.

Backup method selection:

| Backup Method | How to Use | Risk |
| --- | --- | --- |
| `Index` / Plain words | Most basic, must know | If seen, someone can steal funds |
| `Raw Entropy` | Precise BIP39 verification and advanced backup | Leak = same as mnemonic leak |
| `QR Code` | Quick migration or recovery drill | No photos, no phone storage |
| `Encrypted` / KEF | Additional file backup | Must protect both file and password |
| `Dot Matrix` / `Steel Plate` / `1248` | Metal long-term backup | Errors found only through recovery drills |
| `Write Card` | Write to Satochip or SeedKeeper, entry at `Home -> Mnemonic -> Write Card`, NOT in `Backup` submenu | Complex PIN/PUK management; wrong/written cards hard to recover |

For complete backup details, see [BACKUP_AND_RECOVERY_GUIDE.md](BACKUP_AND_RECOVERY_GUIDE.zh-CN.md).

## 9. Using BIP39 Passphrase

A BIP39 passphrase (also called passphrase or password phrase) is not a "login password." It is an additional factor that participates in seed derivation and changes all wallet fingerprints and addresses.

Path:

```text
Home -> Mnemonic -> Passphrase
```

Rules:

| Mnemonic | Passphrase | Result |
| --- | --- | --- |
| Same mnemonic set | Empty | Wallet A |
| Same mnemonic set | `abc` | Wallet B |
| Same mnemonic set | `ABC` | Wallet C |

After using a passphrase, your backup must include both the "mnemonic" and the "passphrase." Losing either means you cannot recover the same wallet.

## 10. Viewing Addresses and Public Keys

Common entries:

```text
Home -> Mnemonic -> Local Mnemonic -> Public Key
Home -> Mnemonic -> Local Mnemonic -> Derived Address
Home -> Connect Wallet -> Derived Address
```

You should verify:

| Item | Why |
| --- | --- |
| Network | Mainnet and testnet addresses differ |
| Address Type | legacy, nested SegWit, native SegWit, Taproot are different |
| Derivation Path | `m/84'/0'/0'` and `m/49'/0'/0'` are not the same wallet view |
| Account Number | account 0, account 1 differ |
| Passphrase | With or without passphrase is completely different |

Extended public keys cannot spend funds but expose your address and transaction history. Do not share publicly with unrelated parties.

## 11. Connecting a BTC Watch-Only Wallet

We recommend using watch-only wallets for receiving and constructing PSBTs, with KernSigner only doing offline signing.

On KernSigner, display public key:

```text
Home -> Connect Wallet -> BTC -> Mnemonic -> zpub
```

Or smart card source:

```text
Home -> Connect Wallet -> BTC -> Smart Card -> zpub
```

If your wallet needs legacy observation public key, choose:

```text
Home -> Connect Wallet -> BTC -> Mnemonic -> xpub
```

Usage steps:

1. KernSigner displays `zpub` or `xpub` QR code.
2. Phone or computer wallet selects import watch-only wallet.
3. Scan KernSigner's QR code.
4. Wallet generates first receiving address.
5. Go back to KernSigner and view the same-path address.
6. Once both addresses match, only send small test amounts.

If addresses don't match, do NOT receive funds.

## 12. BTC PSBT Signing

Recommended main flow: Local mnemonic signing. Do NOT advertise Satochip BTC PSBT card signing as production-ready.

Steps:

1. Watch-only wallet creates transaction.
2. Wallet displays PSBT QR code.
3. On KernSigner, go to:

```text
Home -> QR Sign
```

4. Scan the PSBT with KernSigner camera.
5. For multi-page QR codes, scan from frame 1 through completion.
6. On KernSigner, verify recipient address, amount, change address, fees, and network.
7. If prompted `Enter PIN`, enter device PIN.
8. Confirm signing one final time.
9. KernSigner displays signed result QR code.
10. Watch-only wallet scans back the signed PSBT or transaction.
11. Broadcast from watch-only wallet.

Cancel if ANY of these occur:

- Recipient address is wrong.
- Amount is wrong.
- Change address is unrecognized.
- Fees are abnormal.
- Network mismatch.
- Page content is incomprehensible.

## 13. Connecting Web3 Wallets

Supported entries include:

```text
OKX / Bitget / imToken / MetaMask / Rabby / TokenPocket
```

KernSigner generates connection QR code:

```text
Home -> Connect Wallet -> OKX -> Mnemonic
Home -> Connect Wallet -> OKX -> Smart Card
```

Replace `OKX` with `Bitget`, `imToken`, `MetaMask`, `Rabby`, or `TokenPocket` as needed.

On your phone or browser wallet, look for entries like:

```text
Hardware Wallet
Connect Hardware Wallet
Keystone
QR-based
Scan to connect cold wallet
```

DO NOT select:

```text
Import Mnemonic Phrase
Import Private Key
Import seed phrase
Import private key
```

After connection, your phone wallet only shows watch-only or hardware accounts. Real signing still happens on KernSigner or the smart card.

## 14. Web3 QR Code Signing

Steps:

1. Initiate a test transfer, approval, or DApp operation in OKX, Bitget, imToken, MetaMask, Rabby, or TokenPocket.
2. Wallet displays pending signature QR code.
3. On KernSigner, go to:

```text
Home -> QR Sign
```

4. KernSigner scans the signature request QR from phone/computer.
5. When prompted for source, select the same source you used during connection:

```text
Mnemonic
Smart Card
```

6. Using mnemonic source: enter device PIN or confirm as prompted.
7. Using smart card source: only enter Satochip PIN when you see `Smart Card PIN`.
8. On KernSigner, verify chain, from address, to address, amount, Gas, DApp, contract, and authorization.
9. If you can't understand it, cancel.
10. After confirming signing, KernSigner displays signed result QR code.
11. Phone wallet scans back the result.
12. Phone wallet confirms final broadcast.

Web3 is especially dangerous with approvals and contract calls. If KernSigner cannot clearly display it or you don't understand it, do NOT sign.

## 15. What If QR Codes Are Too Dense

Follow these steps:

1. Before scanning high-density signature QR codes on small phone screens, first adjust the OV5647 camera focus using a standard black-and-white QR code: hold at 10-20 cm distance, gently rotate the outer ring of the camera lens until QR code edges and small cells are clearest. Only twist the lens outer ring; do not twist the flex cable or camera PCB.
2. Increase phone screen brightness.
3. Ensure the QR code is fully displayed, not obscured by borders, buttons, or notches.
4. Keep KernSigner 10-20 cm from the screen.
5. Avoid reflections; do not scan at an angle.
6. If the phone QR code is too small, screenshot or cast to a computer and enlarge the QR code to center of screen.
7. For dynamic QR codes, hold steady for several seconds from frame 1; do not move frequently.
8. If OKX dot-based dynamic codes are completely unresponsive, first check [QR Camera Troubleshooting Guide](QR_CAMERA_TROUBLESHOOTING.zh-CN.md) for focus, image decoding, and UR fragment issues.
9. If still failing, save clear photos or short screen recordings for developers to verify with desktop `zbarimg` / `components/zbar_qr/test`.

## 16. Using Satochip

Satochip is primarily used for smart card signing and account reading. Currently usable as a test card flow; do NOT advertise as an audited production capability.

First use of a blank Satochip:

1. Connect powered OTG, card reader, and Satochip in the correct chain.
2. Go to:

```text
Home -> Self-Test -> Smart Card
```

3. Confirm you can see the card reader, ATR, and Satochip.
4. Go to:

```text
Home -> Smart Card -> Satochip -> Maintenance -> Set PIN
```

5. Set Satochip PIN and record it safely.
6. Prepare your local test mnemonic phrase and confirm you have a paper backup.
7. Confirm this is a blank test card, or that the card's existing seed can be overwritten; if unsure, STOP immediately — do not write to the card.
8. Write to Satochip:

```text
Home -> Mnemonic -> Write Card -> Satochip
```

Or:

```text
Home -> Smart Card -> Satochip -> Write
```

9. After writing, verify addresses via `Address`, `BTC Public Key`, or `Connect Wallet -> Wallet Name -> Smart Card`.

Common Satochip paths:

| Purpose | Path |
| --- | --- |
| View card info | `Home -> Smart Card -> Satochip -> Info` |
| View EVM/BTC path address | `Home -> Smart Card -> Satochip -> Address` |
| Export BTC watch-only key | `Home -> Smart Card -> Satochip -> BTC Public Key` |
| Web3 connection | `Home -> Connect Wallet -> Wallet Name -> Smart Card` |
| Web3 signing | `Home -> QR Sign -> Scan Request -> Smart Card` |
| Change PIN / unlock / reset | `Home -> Smart Card -> Satochip -> Maintenance` |

Do NOT guess card PINs repeatedly. Stop when only 1 attempt remains.

## 17. Using SeedKeeper

SeedKeeper is primarily used for storing mnemonics, passwords, descriptors, and other secrets. It is NOT another name for Satochip, nor is it a direct Web3 signing card; after importing from SeedKeeper to local, subsequent signing sources are treated as `Mnemonic`.

First use of a blank SeedKeeper:

1. Connect powered OTG, card reader, and SeedKeeper.
2. Go to:

```text
Home -> Self-Test -> Smart Card
```

3. Confirm the card is recognized.
4. Go to:

```text
Home -> Smart Card -> SeedKeeper -> Set PIN
```

5. Set SeedKeeper PIN.
6. Write current mnemonic:

```text
Home -> Mnemonic -> Write Card -> SeedKeeper
```

7. First list entries:

```text
Home -> Smart Card -> SeedKeeper -> List
```

8. To view the card's mnemonic, enter `View`. This exposes secrets; only do this in an offline, unobstructed camera environment with no bystanders and no screenshots/screen recordings.
9. After importing to local, verify wallet fingerprint and first address.

Common SeedKeeper paths:

| Purpose | Path |
| --- | --- |
| View status | `Home -> Smart Card -> SeedKeeper -> Status` |
| Set PIN | `Home -> Smart Card -> SeedKeeper -> Set PIN` |
| Change PIN | `Home -> Smart Card -> SeedKeeper -> Change PIN` |
| View space | `Home -> Smart Card -> SeedKeeper -> Remaining Space` |
| List entries | `Home -> Smart Card -> SeedKeeper -> List` |
| Create mnemonic | `Home -> Smart Card -> SeedKeeper -> Create` |
| Write current mnemonic | `Home -> Smart Card -> SeedKeeper -> Write` |
| View card mnemonic | `Home -> Smart Card -> SeedKeeper -> View` |
| Import from card to local | `Home -> Smart Card -> SeedKeeper -> Import` |
| Store password | `Home -> Smart Card -> SeedKeeper -> Store Password` |
| Store descriptor | `Home -> Smart Card -> SeedKeeper -> Store Descriptor` |
| Read descriptor | `Home -> Smart Card -> SeedKeeper -> Read Descriptor` |

SeedKeeper reset is a high-risk operation that clears all secrets on the card. Only proceed if you confirm you have paper or other offline backups AND this is indeed the test card to be cleared. New version SeedKeeper is not old `B0 FF`; follow the wrong PIN/wrong PUK to `FF00` flow. For detailed steps, see [SMARTCARD_SATOCHIP_SEEDKEEPER_OPERATION_GUIDE.md](SMARTCARD_SATOCHIP_SEEDKEEPER_OPERATION_GUIDE.zh-CN.md).

## 19. Daily Safe Exit

After each session:

1. Return to Home.
2. Choose Clear Session or Shutdown/Power Off.
3. Unplug USB.
4. Store paper backups securely.
5. Check phone gallery, screenshots, and clipboard for no mnemonics.
6. Remove smart card and store separately.

The device will auto-lock, but do not rely solely on auto-lock.

## 20. Beginner's First Complete Acceptance Checklist

Follow this order:

1. Confirm hardware is `Waveshare ESP32-P4-WiFi6-Touch-LCD-4.3`.
2. Verify firmware SHA256.
3. Flash `full.bin`.
4. Boot and set device PIN.
5. Enter home page.
6. Run `Self-Test -> System`.
7. Run `Self-Test -> Peripherals -> Touch`.
8. Run `Self-Test -> Peripherals -> Camera`.
9. Create test mnemonic using `Hex`.
10. View raw entropy, verify with offline BIP39 tool.
11. Write down mnemonic on paper.
12. Clear session.
13. Manually import mnemonic.
14. Verify fingerprint and address.
15. Connect BTC watch-only wallet, export `zpub`.
16. Perform one test PSBT signing.
17. Connect a Web3 wallet, e.g., OKX or Bitget.
18. Perform one small test signature.
19. If using smart card, connect powered OTG then run `Self-Test -> Smart Card`.
20. Use test card to run Satochip or SeedKeeper flow.
21. Save version number, firmware SHA256, test results, and issue screenshots.

If this is a fresh-flash initial acceptance, also complete this minimum checklist:

| # | Check Item | Pass Criteria |
| --- | --- | --- |
| 1 | Boot | Can enter startup page or home; no continuous reboot, panic, assert, watchdog in serial |
| 2 | Touch | Main menu, back button, return to home all work normally |
| 3 | Brightness | Brightness change is visible; no black screen or touch failure |
| 4 | Camera preview | Image visible, orientation reasonable, can return stably |
| 5 | QR code classification | Standard text, URL, public收款 URI recognized; risky content uses only test data |
| 6 | Storage card | FAT32 card read/write, read-only browsing, statistics and security filtering normal; if case blocks slot, record as untested |
| 7 | About page | Version and Chinese info display and return correctly |
| 8 | Self-Test/Delivery page | Can see firmware version, hardware snapshot, feature boundaries |
| 9 | Wallet flow | Using only test mnemonic, test PSBT, test Web3 request to verify loading, import, address, backup, signing, cancel, and export |

Before delivering to others, at minimum collect:

```text
Firmware Version:
Build Time:
Source commit:
Firmware SHA256:
boot.log:
Acceptance photos/screenshots:
Failed items:
Reproduction steps:
```

Production candidates must also include `PRODUCTION_CHECK.txt`, `MANUFACTURING_READINESS.txt`, signed images, and flashing records. Do NOT mark as commercial production version until `prodcheck` passes.

## 21. When to Stop Immediately

Stop when you encounter:

- Device PIN has only one attempt remaining.
- Smart card PIN or PUK has only one attempt remaining.
- Phone wallet address does not match KernSigner address.
- Signing page shows incomprehensible amounts, contracts, or authorizations.
- Flash verification failed.
- Unsure whether flashing test version or production version.
- Smart card reader light flashes only once.
- Page repeatedly crashes or reboots.

After stopping, first record the page title, exact error message, what you just tapped, firmware version, and serial logs before continuing troubleshooting.
