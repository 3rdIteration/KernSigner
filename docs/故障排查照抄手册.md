# KernSigner Troubleshooting Step-by-Step Guide

Date: 2026-05-22

This document does one thing only: follow the tables below step-by-step when problems occur. Do NOT repeatedly enter PINs, fully erase everything, or flash wrong firmware images when uncertain.

## Stop These Three Things First

When a problem occurs, stop immediately:

1. Do not continue entering PINs, especially when only one attempt remains.
2. Do not continue signing, especially when addresses, amounts, or contracts are incomprehensible.
3. Do NOT fully erase or randomly flash; first save logs and symptoms.

Record these 6 items first:

```text
1. Firmware Version:
2. Hardware Model:
3. Current Page Title:
4. Exact Error Message:
5. What You Just Tapped:
6. Whether There Are Serial Logs/Photos/Videos:
```

Photos, screenshots, and screen recordings must NOT contain mnemonics, raw entropy, PINs, PUKs, private keys, or card recovery codes; signature request QR codes may also leak addresses, amounts, and DApp info. Delete troubleshooting materials promptly after use and disable automatic cloud sync.

## Quick Diagnosis Table

| Symptom | Stop Doing | Follow These Steps | Information to Collect |
| --- | --- | --- | --- |
| Black screen on boot | Stop repeatedly flashing app-only | Change cable for power, confirm `wave_43`, capture serial logs, flash full package if necessary | Serial logs, flashing command, firmware filename |
| Garbled/white screen | Stop acceptance testing | Confirm board model and firmware, adjust brightness, restart, capture logs | Screen photos, board model |
| Inaccurate touch | Stop entering mnemonics | Restart, tap with finger directly, go to `Self-Test -> Peripherals -> Touch` | Touch position photos/videos |
| Camera black screen | Stop continuously tapping | Wait 2-3 seconds, go back and re-enter, restart, run camera self-test | Page path, logs |
| QR code not scanning | Don't declare signing failure | Before first scan of small high-density signature codes, adjust OV5647 lens focus with standard QR: 10-20 cm, gently rotate outer ring; then adjust brightness, avoid reflections, screenshot or cast to computer | QR code type, wallet name, whether focused |
| PSBT signing fails | Don't broadcast | Verify fingerprint, network, change, fees, rescan from frame 1 | PSBT source wallet, exact error message |
| Web3 signing fails | Don't blindly sign | Check wallet, chain, from, to, authorization, QR density | Wallet name, chain, request type |
| Connected wallet address mismatch | Don't receive funds | Check mnemonic, passphrase, path, account number, network, source | KernSigner address, wallet address |
| Smart card not detected | Don't guess PIN | Check powered OTG, port, reader light, `Self-Test -> Smart Card` | Wiring photos, ATR/errors |
| SeedKeeper reset returns `9C20` | Don't assume power issue | Use new version flow: wrong PIN/wrong PUK to `FF00` | Return code, card type |
| Don't know which PIN to enter | Stop guessing | Check page title; `Enter PIN` = device PIN, `Smart Card PIN` = card PIN | Page photos |
| Flashing same old version | Stop random flashing | Confirm directory, serial port, bin SHA256, flash address, whether restarted | `sha256sum`, flashing logs |

## 1. Flashing Issues

### 1.1 Don't Know Whether to Flash Full or App

Judge by this:

| Device State | Should Flash |
| --- | --- |
| New board, blank board, unknown firmware | Full package to `0x0` |
| Already running KernSigner, only upgrade app | App package to `0x20000` |
| Partition table uncertain | Full package |
| Bootloader uncertain | Full package |
| Just a small UI or feature update, device already running this project properly | App package |

Do NOT flash an app-only package onto a blank board.

### 1.2 Linux Flashing — Follow Exactly

```bash
cd /home/ak/123/KernSigner/firmware/wave_43
sha256sum -c SHA256SUMS.txt
./flash_wave43_linux.sh /dev/ttyACM0
```

If `/dev/ttyACM0` does not exist:

```bash
ls /dev/ttyACM*
ls /dev/ttyUSB*
```

### 1.3 Check These First If Flashing Fails

1. Is the USB cable a data cable?
2. Are you plugged into the download port, not the OTG peripheral port?
3. Is the serial port correct?
4. Did firmware SHA256 pass verification?
5. Is another serial monitor occupying the port?
6. Did you flash full vs app incorrectly?

## 2. Boot and Screen Issues

### 2.1 Black Screen

Follow these steps:

1. Change USB cable and computer USB port.
2. Confirm board is `Waveshare ESP32-P4-WiFi6-Touch-LCD-4.3`.
3. Confirm flashing `wave_43` firmware.
4. If new board, flash full package.
5. Capture serial logs.
6. If serial is normal but screen is black, suspect wrong board model flashed, screen initialization, or backlight issues.

### 2.2 Inaccurate Touch

Follow these steps:

1. Restart device.
2. Remove thick protective film or gloves.
3. Go to:

```text
Home -> Self-Test -> Peripherals -> Touch
```

4. Record which areas are inaccurate.
5. Confirm you did not flash another board model's firmware.

## 3. PIN Issues

### 3.1 Determine Which PIN to Enter

| Screen Text | What to Enter |
| --- | --- |
| `Enter PIN` | Device PIN |
| `Set PIN` | New device PIN |
| `Smart Card PIN` | Satochip/SeedKeeper PIN |
| `Old PIN` / `New PIN`, in smart card menu | Smart card old/new PIN |
| `PUK` | Smart card PUK |

### 3.2 Forgot Device PIN

There is NO way to recover from the device itself. You can only rely on mnemonics, KEF, smart cards, or other backups to re-restore.

Do NOT try randomly first. Figure out where your backups are before dealing with the device.

### 3.3 Smart Card PIN Has One Attempt Left

Stop immediately:

1. Do not guess again.
2. Find card PIN/PUK records.
3. Only enter after confirmation.
4. If unsure, use official tools or maintenance flows.

## 4. Mnemonic and Address Issues

### 4.1 BIP39 Website Results Don't Match

Check in order:

1. Is the website language `English`?
2. Was it opened offline?
3. Is `Show entropy details` checked?
4. Is `Entropy Type` correct?
5. Is `Mnemonic Length` set to `Use Raw Entropy`?
6. What you copied from KernSigner is `Hex` raw entropy, not other fields.
7. Did you miss or add extra entries for dice, coins, or playing cards?
8. For D20, do NOT directly paste from websites; first verify with KernSigner's hex raw entropy.

### 4.2 Restored Address Doesn't Match

Troubleshoot in this order:

| Check | Description |
| --- | --- |
| Words | Are they exactly the same? |
| Order | Is the sequence correct? |
| Word Count | Is 12/15/18/21/24 consistent? |
| Passphrase | Is there a passphrase? |
| Network | Mainnet/testnet? |
| Path | `m/84'/0'/0'` etc. |
| Address Type | legacy / nested SegWit / native SegWit / Taproot |
| Account Number | account 0 or account 1? |

If any item differs, addresses will likely be different.

## 5. QR Code Scanning Issues

For the complete dedicated QR scanning flow, see [QR Camera Troubleshooting Guide](QR_CAMERA_TROUBLESHOOTING.md). Here is the shortest follow-exactly version.

### 5.0 ESP32-P4 4.3 First-Time Camera Focus Adjustment

After first using this board, replacing the camera, replacing the flex cable, installing a case, or moving the camera position, do this section first.

Follow these steps:

1. Open:

```text
Home -> Self-Test -> Peripherals -> Camera
```

2. Display a standard black-and-white QR code on your phone or computer.
3. Keep distance at 10-20 cm, increase screen brightness, avoid reflections.
4. Pinch the OV5647 camera lens outer ring and gently rotate.
5. Stop when QR code edges and small cells appear clearest.
6. Only twist the lens outer ring; do NOT twist the flex cable, pull the camera PCB, or let FFC gold fingers loosen.
7. Once standard QR codes scan reliably, test high-density dynamic codes from OKX, Bitget, TokenPocket, etc.

Judgment:

| Symptom | Conclusion |
| --- | --- |
| Standard QR code recognized quickly | Focus is basically usable |
| Standard QR code never responds | Continue adjusting focus, distance, brightness, angle |
| Only OKX dot codes unresponsive | Continue to section 5.1 and QR dedicated guide |
| Progress bar appears but no signing jump | Image layer recognized; check fragments, format, signature parsing |

### 5.1 KernSigner Cannot Scan QR Codes

Follow these steps:

1. First confirm standard QR code focus from 5.0 has passed.
2. Increase phone brightness.
3. Keep device and phone 10-20 cm apart.
4. Ensure QR code is fully displayed, not obscured by borders.
5. Do NOT scan at an angle.
6. Avoid strong reflections.
7. If QR code is very small or dense, screenshot or cast to computer to enlarge.
8. For dynamic codes, scan completely from frame 1.
9. Go back to home and re-enter `QR Sign`.
10. Still failing? Save photos or screen recordings, then verify with desktop `zbarimg` / `components/zbar_qr/test` first.

### 5.2 Phone Cannot Scan Back KernSigner Results

Follow these steps:

1. Tap KernSigner's large code display or fragment display.
2. Increase KernSigner screen brightness.
3. Keep phone 10-20 cm from screen.
4. Ensure no reflections.
5. Confirm phone wallet is on "scan signature result" page, not regular home page scanner.

## 6. BTC Issues

### 6.1 Watch Wallet Balance or Address Wrong After Import

Check:

1. Did you import `zpub` or `xpub`?
2. Is the address type selected in phone wallet consistent?
3. Are mainnet/testnet settings consistent?
4. Was a passphrase used?
5. Is there an account number mismatch?

### 6.2 PSBT Signing Fails

First check KernSigner prompts:

| Prompt/Symptom | Action |
| --- | --- |
| Not current wallet | Verify fingerprint and xpub |
| Unrecognized change | Check descriptor, path, wallet type |
| Network mismatch | Mainnet and testnet cannot be mixed |
| QR code missed scanning | Rescan from frame 1 |
| Abnormal fees | Cancel, reconstruct transaction |

Do NOT relax checks just to complete the flow.

## 7. Web3 Issues

### 7.1 Wallet Connection QR Won't Scan

1. Confirm phone wallet selected `Hardware Wallet`, `Keystone`, or `QR-based`.
2. Do NOT use regular home page scanner.
3. Do NOT select import mnemonic.
4. Regenerate the corresponding wallet QR code on KernSigner.
5. Confirm source is `Mnemonic` or `Smart Card`.

### 7.2 Web3 Signing Fails

Check in order:

1. Is the wallet OKX, Bitget, MetaMask, Rabby, or TokenPocket?
2. Is the request type currently open/available?
3. Was TypedData/EIP-712 rejected; this is a security boundary, not a regular fault.
4. Is the chain ID correct?
5. Is the from address your KernSigner account?
6. Is the signing source consistent with the connection source?
7. Is the smart card PIN correct and remaining attempts sufficient?
8. Is the QR code too dense; need to screenshot or cast to computer to enlarge?
9. If OKX dot-based dynamic codes are completely unresponsive, first check [QR_CAMERA_TROUBLESHOOTING.md](QR_CAMERA_TROUBLESHOOTING.zh-CN.md), do NOT directly modify signing protocols; for incident details also see [OKX_QR_SCAN_INCIDENT_20260523.md](OKX_QR_SCAN_INCIDENT_20260523.zh-CN.md).

## 8. Smart Card Issues

### 8.1 Reader Light Flashes Only Once

Primarily suspect insufficient power.

Follow these steps:

1. Change to a powered OTG adapter cable.
2. Or change to a truly externally powered USB Hub.
3. Confirm the reader is downstream of the Hub.
4. Do NOT plug into the download port.
5. Then go to:

```text
Home -> Self-Test -> Smart Card
```

### 8.2 Can See Hub, Cannot See Reader

1. Confirm the Hub itself has external power.
2. Change USB port downstream of Hub.
3. Replace reader.
4. Change OTG direction.
5. Save wiring photos.

### 8.3 Has ATR, But APDU or Signing Fails

Possible causes:

- Power edge instability.
- Card not fully seated.
- Wrong PIN.
- Card applet state incorrect.
- Request type is not an open capability.

Handling:

1. Re-insert card.
2. Re-enter `Self-Test -> Smart Card`.
3. Read status first, then do connection codes.
4. After connection code succeeds, test signing.
5. If failing, save return codes.

### 8.4 SeedKeeper Reset

If you get `9C20`, do NOT assume driver is broken.

New version SeedKeeper uses:

```text
Home -> Smart Card -> SeedKeeper -> Reset
```

**Reset will clear ALL secrets on the card. Only proceed if you confirm you have paper or other offline backups AND this is indeed the test card to be cleared.**

Then:

1. Enter a definitely wrong PIN, e.g., `0000`.
2. Tap `Wrong PIN Step 1` until PIN is locked.
3. Enter a definitely wrong PUK, e.g., `0000`.
4. Tap `Wrong PUK Step 1` until returning `FF00`.
5. Re-insert card.
6. Re-`Set PIN`.

Do NOT enter real PIN or real PUK to perform a reset.

## 9. Build Issues

### 9.1 Firmware Build Fails

First confirm:

```bash
cd /home/ak/123/KernSigner
git submodule update --init --recursive
. ~/esp/esp-idf-v5.5.4/export.sh
idf.py -B build_wave_43_fresh \
  -D SDKCONFIG=build_wave_43_fresh/sdkconfig \
  -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.defaults.wave_43' \
  build
```

Common causes:

- ESP-IDF not loaded.
- Wrong ESP-IDF version.
- Submodules not pulled.
- Build directory mixed up.
- Changed code but flashing old bin.
