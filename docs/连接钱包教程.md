# KernSigner Wallet Connection and QR Signing Tutorial

Date: 2026-05-21

This tutorial is for anyone using KernSigner for the first time. The goal: when you hold the development board, phone wallet, or computer wallet, you know where to tap, which QR code to scan, which PIN to enter, and what information to verify.

**KernSigner is currently still in test fund acceptance mode**, not an audited commercial production wallet. Do not import real mnemonic phrases or store real assets until you have completed the commercial release gate, device acceptance testing, and independent security audit; use only test mnemonics, testnet assets, or small acceptance funds you can explicitly afford to lose.

## Read This First — 1 Minute Overview

| Task | Correct Approach |
|---|---|
| Web3 wallet connection | In OKX, Bitget, MetaMask, Rabby, TokenPocket, select `Hardware Wallet`, `Connect Hardware Wallet`, `Keystone`, or `QR-based`, then scan the Keystone-compatible QR code shown on KernSigner |
| What NOT to do | Do NOT import KernSigner mnemonics, smart card mnemonics, or private keys into phone wallets or browser extensions |
| BTC wallet connection | Import the `zpub` or `xpub` shown on KernSigner as a read-only watch-only wallet |
| Web3 signing | Phone/extension displays pending signature QR code → KernSigner enters `QR Sign` to scan → verify complete info → sign → phone/extension scans back the signed result |
| BTC signing | BTC wallet generates PSBT QR code → KernSigner enters `QR Sign` to scan → verify recipient address, change, and miner fees → sign → scan signed PSBT back to wallet for broadcast |
| PIN | Screen says `Enter PIN` = usually device PIN; screen says `Smart Card PIN` = enter Satochip/SeedKeeper card PIN |

## How to Choose Signing Source on KernSigner

KernSigner currently has two signing source types.

| Source | Suitable For | Which PIN Needed |
|---|---|---|
| `Mnemonic` | Local mnemonic already loaded into KernSigner board memory | Enter device PIN when page shows `Enter PIN` |
| `Smart Card` | Satochip signing card plugged into USB card reader | Enter smart card PIN when page says `Smart Card PIN` |

Satochip is a signing card; SeedKeeper is primarily used to save or generate secrets. After importing a SeedKeeper entry to local, subsequent signing sources should be understood as `Mnemonic`; do NOT treat SeedKeeper as a direct Web3 signing card.

Simplest judgment:

| What You Want to Do | What to Select on KernSigner |
|---|---|
| Connect Web3 using mnemonic already loaded in board | `Connect Wallet -> Wallet Name -> Mnemonic` |
| Connect Web3 using Satochip smart card | `Connect Wallet -> Wallet Name -> Smart Card` |
| Export BTC watch-only wallet using board mnemonic | `Connect Wallet -> BTC -> Mnemonic -> zpub` |
| Export BTC watch-only wallet using Satochip smart card | `Connect Wallet -> BTC -> Smart Card -> zpub` |
| Use board mnemonic for Web3 signing | After `QR Sign`, select `Mnemonic` |
| Use Satochip card for Web3 signing | After `QR Sign`, select `Smart Card` |
| BTC PSBT signing | Current acceptance main line prioritizes board mnemonic; Satochip BTC card PSBT signing is NOT claimed as production-ready |

If your firmware version's menu has a first-level `Web3 Wallet` or `Bitcoin Wallet`, enter that layer first, then continue by wallet name. Current menu is typically:

```text
Home -> Connect Wallet -> OKX / Bitget / imToken / MetaMask / Rabby / TokenPocket / Keystone / BTC
```

## Web3 Wallet Connection General Rules

Web3 commercial wallets include:

```text
OKX Wallet / Bitget Wallet / imToken / MetaMask / Rabby / TokenPocket
```

Users have already tested these wallets with test funds/small acceptance amounts for connection, QR code signing, and signed result transmission:

| Wallet | Tested Status |
|---|---|
| OKX Wallet | Connection code, dot/high-density dynamic signature codes, signed result back — all passed |
| Bitget Wallet | Connection code, test transfer signing, signed result back — all passed |
| imToken | Single-account connection, `eth-sign-request` signing, `eth-signature` back — all passed |
| MetaMask | Single-account connection, QR code signing, signed result back — all passed |
| Rabby | Keystone/QR compatible connection, test fund Web3 signing — passed |
| TokenPocket | Connection, dynamic/multi-page QR code signing, signed result back — all passed |
| BlueWallet | BTC watch wallet, PSBT QR signing and result back — passed |
| Electrum | BTC watch wallet, PSBT/signed transaction QR flow — passed |

These conclusions only indicate that the current firmware can complete signing in test fund flows with the above wallets; they do NOT mean production auditing is complete.

When connecting KernSigner in these wallets, ALWAYS avoid:

```text
Import Mnemonic Phrase
Import Private Key
Import seed phrase
Import private key
Create new wallet and copy mnemonic there
```

You MUST select entries like:

```text
Hardware Wallet
Connect Hardware Wallet
Connect Hardware Wallet
Keystone
QR-based
Cold Wallet
Scan to connect Keystone
```

The reason is simple: phone wallets and browser extensions only handle network connectivity, balance checking, transaction initiation, and broadcasting. Private keys remain in KernSigner development board or smart cards; signing is passed back and forth via QR codes.

## Web3: Generate Connection QR Code on KernSigner

Using OKX as an example; for other wallets, just replace the wallet name with Bitget, imToken, MetaMask, Rabby, or TokenPocket.

### Connect Using Board Mnemonic

1. Confirm you have already loaded or created a mnemonic in KernSigner.
2. On KernSigner home page, go to:

```text
Connect Wallet -> OKX -> Mnemonic
```

3. If `Enter PIN` pops up, enter the device PIN.
4. KernSigner displays connection QR code.
5. If the QR code has multiple fragments, keep the page displayed fully for the phone or browser to continue scanning; if there's a `Show Large Code` option and scanning fails, tap `Show Large Code` first.
6. In OKX wallet, select Hardware Wallet/Keystone to scan this QR code.

### Connect Using Smart Card

1. Plug in externally powered USB card reader.
2. Insert Satochip/SeedKeeper smart card into the reader.
3. Recommended to run once:

```text
Device Check -> Smart Card
```

4. Confirm you can identify the card reader, ATR, and Satochip/SeedKeeper.
5. On KernSigner home page, go to:

```text
Connect Wallet -> OKX -> Smart Card
```

6. When screen says `Smart Card PIN`, enter the smart card PIN, NOT the device PIN.
7. After KernSigner reads account info from the card, it displays the connection QR code.
8. In OKX wallet, select Hardware Wallet/Keystone to scan this QR code.

### Path for Each Web3 Wallet on KernSigner

| Wallet | Board Mnemonic Path | Smart Card Path |
|---|---|---|
| OKX Wallet | `Connect Wallet -> OKX -> Mnemonic` | `Connect Wallet -> OKX -> Smart Card` |
| Bitget Wallet | `Connect Wallet -> Bitget -> Mnemonic` | `Connect Wallet -> Bitget -> Smart Card` |
| imToken | `Connect Wallet -> imToken -> Mnemonic` | `Connect Wallet -> imToken -> Smart Card` |
| MetaMask | `Connect Wallet -> MetaMask -> Mnemonic` | `Connect Wallet -> MetaMask -> Smart Card` |
| Rabby | `Connect Wallet -> Rabby -> Mnemonic` | `Connect Wallet -> Rabby -> Smart Card` |
| TokenPocket | `Connect Wallet -> TokenPocket -> Mnemonic` | `Connect Wallet -> TokenPocket -> Smart Card` |
| Keystone | `Connect Wallet -> Keystone -> Mnemonic` | `Connect Wallet -> Keystone -> Smart Card` |

`Keystone` is suitable for other wallets supporting the Keystone/QR hardware wallet protocol. When you can select a specific wallet name, prefer the connection code corresponding to that wallet name.

## OKX Wallet Connection Tutorial

Button names on mobile or extension may vary by version; look for similar meanings.

1. Open OKX Wallet.
2. Go to Add Wallet or Accounts page.
3. Select:

```text
Hardware Wallet
Keystone
```

4. If OKX prompts for camera permission, allow it.
5. Use OKX to scan the OKX connection QR code on KernSigner.
6. If OKX asks you to choose an account, select the first common account first.
7. If unsure about derivation path, do NOT randomly switch Ledger/Legacy paths; use the default account first, then verify address consistency with small test amounts.
8. After successful connection, what you see in OKX is a watch account that cannot spend funds independently; signing still requires KernSigner.

Common pitfalls:

| Problem | Solution |
|---|---|
| OKX scans but nothing happens | Confirm you selected `Hardware Wallet -> Keystone` in OKX, NOT regular scan |
| QR code has multiple fragments | Keep KernSigner page lit; continue scanning completely as wallet prompts |
| Address doesn't match | Check whether KernSigner selected `Mnemonic` or `Smart Card`, and whether OKX account selection switched paths |

## Web3 QR Code Signing Tutorial

Wallet connection is done once or occasionally. When money is truly at stake, every transaction goes through the signing flow.

### Initiate Signing on Phone or Extension

1. Initiate a transfer, approval, Swap, or DApp operation in OKX, Bitget, imToken, MetaMask, Rabby, or TokenPocket.
2. Wallet displays pending signature QR code.
3. Do NOT rush to scan; first review the recipient address, amount, chain, Gas, and DApp name on your phone wallet.

### KernSigner Scans QR Code

1. On KernSigner home page, go to:

```text
QR Sign
```

2. Use KernSigner camera to scan the pending signature QR code from your phone or computer.
3. If KernSigner identifies it as a Web3 request, it will first ask you to choose:

```text
Mnemonic
Smart Card
```

4. If you connected the wallet using board mnemonic, select `Mnemonic`.
5. If you connected the wallet using Satochip smart card, select `Smart Card`.

### Verify Complete Transaction Info on KernSigner

Before signing, you MUST verify on the KernSigner screen:

| Information | How to Check |
|---|---|
| Source | Whether `Mnemonic` or `Smart Card` is correct |
| Wallet | Whether OKX, Bitget, imToken, MetaMask, Rabby, TokenPocket matches your initiated wallet |
| Action | Transfer, message signature, transaction signature, approval, etc. |
| Chain | Whether Ethereum, BSC, Polygon, etc. chain is correct |
| DApp | Whether it's the website or app you're actively using |
| Path | Whether derivation path matches the account used during connection |
| Address | Whether the signing request address is your watch account |
| Recipient Address | Whether transfer target is correct |
| Amount | Whether amount and unit match expectations |
| Gas | Whether Gas Limit, Gas Price, Max Fee are outrageous |
| Transaction Data | If it's a contract call, data will be long; if you don't understand, do NOT sign |
| Raw Text | KernSigner displays `Transaction Raw`, `Message Raw`, or `Full TypedData` for verification |

If any item is incomprehensible, inconsistent with your phone wallet, or the DApp is not one you actively opened, directly return and decline to sign.

### Enter PIN and Sign

| Selected Source | Next Step |
|---|---|
| Mnemonic | After verifying, tap `Sign`; if page shows `Enter PIN`, enter device PIN |
| Smart Card | After verifying, tap `Enter PIN`, enter smart card PIN then sign |

After signing completes, KernSigner displays a `Web3 Signature Result` QR code, typically in `eth-signature` format.

### Phone or Extension Scans Back Result

1. Return to the original wallet.
2. Look for `Get Signature`, `Scan Signature Result`, `Next Step`, or similar buttons.
3. Use the original wallet to scan the signature result QR code on KernSigner.
4. After the original wallet recognizes it, confirm broadcast one final time.

Note: KernSigner only signs; it does NOT broadcast Web3 transactions to the chain. Broadcasting is done by OKX, Bitget, imToken, MetaMask, Rabby, or TokenPocket.

## What If Web3 Signing QR Codes Are Too Dense

When encountering these situations, do NOT force-scan:

| Symptom | Solution |
|---|---|
| First time scanning small high-density signature QR codes | First adjust OV5647 lens focus with standard QR: 10-20 cm, gently rotate outer ring; scan wallet QR only after standard QR scans stably |
| KernSigner keeps failing to scan | Screenshot or cast to computer first; enlarge QR code to center of screen |
| Phone QR code is very small | Enlarge the QR code, increase brightness, keep 10-20 cm distance |
| Small high-density QR codes | Screenshot or cast to computer first; enlarge QR code to center of screen then have board scan |
| Dynamic QR codes change quickly | Hold steady from frame 1 for several seconds; if still failing, record screen for developers to extract frames for verification |
| OKX dot codes completely unresponsive | First check focus and image decoding layer, then see QR dedicated guide |
| TokenPocket/Bitget QR too dense | Prioritize computer enlargement; if still failing, collect photos or screen recordings for desktop decoding |

Troubleshooting photos, screenshots, and screen recordings must NOT contain mnemonics, raw entropy, PINs, PUKs, private keys, or card recovery codes; signature request QR codes may also leak addresses, amounts, and DApp info. Delete promptly after troubleshooting to avoid cloud sync.

## TypedData and Approvals — Be Extra Careful

TypedData, EIP-712, Approve, Permit, SetApprovalForAll requests are often NOT regular transfers.

| Type | Risk |
|---|---|
| `Approve` | May authorize a contract to spend your tokens |
| `Permit` | May provide authorization signature without an on-chain transaction |
| `SetApprovalForAll` | In NFT scenarios, may authorize the other party to transfer entire classes of NFTs |
| `TypedData` | Complex content structure; must read full raw text; currently handled only as verification/non-production boundary, NOT as an open signing capability |

Current TypedData/EIP-712 is NOT an open production signing capability. If the page explicitly rejects or indicates not connected, this is a security boundary, NOT a regular fault. Decline if you don't understand it. Whether the DApp pressures you, customer service asks you, or airdrop websites ask you to sign — STOP first.

## BTC Wallet Connection General Rules

BTC wallet connection is NOT the Web3 Keystone connection code. BTC connection typically involves importing the extended public key shown on KernSigner into your phone or computer wallet to generate a read-only watch-only wallet.

| Name | Purpose | Address Type |
|---|---|---|
| `zpub` | Recommended default choice | Native SegWit, addresses usually start with `bc1q` |
| `xpub` | Compatible with old wallets or legacy addresses | Traditional addresses, commonly starting with `1` |
| `ypub` | Nested SegWit | Addresses usually start with `3`, currently mainly viewed in smart card advanced public key page |
| `vpub` | Testnet Native SegWit | Testnet |
| `tpub` | Testnet traditional extended public key | Testnet |
| `upub` | Testnet Nested SegWit | Testnet |

Beginner recommendation:

```text
Mainnet BTC:优先 select zpub
Legacy address compatibility: only then select xpub
Testnet: only use tpub/upub/vpub when explicitly testing
```

Extended public keys cannot directly spend funds, but they expose your receiving addresses, change addresses, and transaction history. Do NOT share them casually.

## BlueWallet Connection Tutorial

BlueWallet is suitable for BTC read-only watch wallets on mobile.

### Import Read-Only Wallet

1. On KernSigner, display:

```text
Connect Wallet -> BTC -> Mnemonic -> zpub
```

Or:

```text
Connect Wallet -> BTC -> Smart Card -> zpub
```

2. Open BlueWallet.
3. Click Add Wallet.
4. Select Import Wallet.
5. Select Scan or Paste.
6. Scan the `zpub` QR code on KernSigner, or manually paste the `zpub` text.
7. Confirm the imported wallet is watch-only / read-only.
8. After entering the wallet, first compare whether the first receiving address matches KernSigner or your expectations.

### Initiate BTC Signing with BlueWallet

1. In BlueWallet watch wallet, click Send.
2. Enter recipient address and amount.
3. Set miner fees.
4. Generate unsigned transaction or PSBT QR code.
5. On KernSigner home page, go to:

```text
QR Sign
```

6. Use KernSigner to scan BlueWallet's PSBT QR code.
7. On KernSigner, verify recipient address, amount, change address, and miner fees.
8. After confirming, enter device PIN and sign.
9. KernSigner displays signed PSBT QR code.
10. BlueWallet scans back the signed result.
11. BlueWallet finally broadcasts the transaction.

If BlueWallet can't find the PSBT/offline signature entry, first use Sparrow or Electrum to accept the BTC signing flow.

## Sparrow Wallet Connection Tutorial

Sparrow is suitable for BTC watch wallets, PSBTs, and hardware wallet acceptance testing on desktop.

### Import zpub/xpub

1. On KernSigner, display `zpub`; beginners should优先 use:

```text
Connect Wallet -> BTC -> Mnemonic -> zpub
```

2. Open Sparrow.
3. Select Create New Wallet.
4. Wallet type: Single Signature.
5. Script type: Native SegWit or P2WPKH.
6. Keystore: `xPub / Watch Only Wallet`, or in Keystore select Import Extended Public Key.
7. Paste the `zpub` shown on KernSigner.
8. If Sparrow asks for fingerprint or derivation path, fill in the default native segwit account path; KernSigner's zpub corresponds to common account path `m/84'/0'/0'`.
9. Click Apply to save.
10. Compare whether the first receiving address is correct.

If you import `xpub`, script type should be Legacy or P2PKH, corresponding path is typically `m/44'/0'/0'`.

### Initiate BTC Signing with Sparrow

1. In Sparrow, go to Send.
2. Enter recipient address, amount, and miner fees.
3. Create transaction.
4. Check transaction details.
5. Export PSBT; select Show QR Code or Copy PSBT.
6. On KernSigner home page, enter `QR Sign`.
7. KernSigner scans Sparrow's PSBT QR code.
8. Verify all outputs on KernSigner.
9. After signing, KernSigner displays signed PSBT QR code.
10. Sparrow scans back or imports the signed PSBT.
11. Sparrow broadcasts the transaction.

## What Must Be Verified Before BTC Signing

After KernSigner scans a PSBT, do NOT just look at your phone wallet. You MUST verify on the KernSigner screen.

| Information | Why It Matters |
|---|---|
| Recipient Address | Prevents clipboard or wallet interface replacement attacks |
| Recipient Amount | Prevents amount modification |
| Change Address | Change should return to your own wallet path |
| Miner Fees | Prevents abnormally high fees |
| Input Count | Large numbers of inputs may expose privacy or cause very high fees |
| Wallet Source | Confirm it's the wallet corresponding to the currently loaded mnemonic |

If you can't understand the change address, do NOT sign yet. You can cross-reference Sparrow/Electrum transaction details with KernSigner's display.

## Common Issues

### What If Phone Wallet Asks for Your Mnemonic

Do NOT enter it. Go back one level and look for `Hardware Wallet`, `Keystone`, `QR-based`, `Cold Wallet`, or `Watch Wallet`.

### Web3 Wallet Doesn't Recognize KernSigner QR Code

Check in order:

1. Whether you scanned from the wallet's Hardware Wallet/Keystone entry.
2. Whether the wallet name selected on KernSigner matches your phone wallet.
3. Whether the QR code is fully displayed, not obscured by borders.
4. If it's OKX dynamic connection code, whether you scanned all fragments.
5. Whether phone camera permission is enabled.
6. Try `Show Large Code` or increase brightness.

### Can Only Select Smart Card, Not Mnemonic When Signing

The current unified Web3 QR entry should show both `Mnemonic` and `Smart Card` buttons. If you only see Smart Card:

1. Confirm you entered from home page `QR Sign`, NOT from the dedicated entry in Smart Card Tools.
2. Confirm firmware includes the latest modifications.
3. Confirm a signable mnemonic is loaded, not a temporary mnemonic.
4. If still incorrect, do NOT sign yet; send screen photos (without mnemonics, PINs, PUKs, private keys, or raw entropy) along with firmware version to developers for troubleshooting.

### Why Can Phone Wallet See Assets After Connection But Cannot Transfer Directly

This is normal. The phone wallet is a watch-only wallet that can only initiate transactions, display balances, and broadcast. Real signing must be completed by KernSigner development board or smart card.

### BTC Address Doesn't Match After Import

Common causes:

| Cause | Solution |
|---|---|
| Used `xpub` but wallet parses as native segwit | Switch to `zpub` or adjust script type |
| Used `zpub` but wallet parses as legacy | Select Native SegWit/P2WPKH in wallet |
| Inconsistent mnemonic source | Confirm whether KernSigner selected `Mnemonic` or `Smart Card` |
| Different account numbers | Beginners use account 0 first, corresponding to common path `m/84'/0'/0'` |
| Mixed mainnet/testnet | Mainnet uses zpub/xpub; testnet uses vpub/tpub/upub |

### What If Smart Card PIN Is Wrong

Stop immediately when you see remaining attempts decreasing; do NOT guess. Smart card PIN errors reaching zero will lock the card. For detailed handling, see:

```text
docs/SECURITY_PIN_GUIDE.md
```

### What If Device PIN Is Wrong

Device PIN wrong 3 consecutive times will clear the current session and shut down or reboot. Stop, confirm your PIN, do NOT keep trying. For detailed handling, see:


## New User Acceptance Order

Do NOT go straight to mainnet large funds for your first time. This order is most stable:

1. Use only test mnemonics or small test funds.
2. Connect OKX using `Connect Wallet -> OKX -> Mnemonic`.
3. Send one small Web3 transfer; KernSigner verifies and signs.
4. Repeat the same small Web3 signing regression with Bitget, imToken, MetaMask, Rabby, TokenPocket in order.
5. Import BlueWallet or Electrum using `Connect Wallet -> BTC -> Mnemonic -> zpub`.
6. Send one small BTC test transaction; KernSigner scans PSBT and signs.
7. Insert smart card, run `Device Check -> Smart Card`.
8. Connect Web3 using `Connect Wallet -> OKX -> Smart Card`.
9. Use only test funds for one Satochip Web3 signing.
10. Only consider larger amounts after you can clearly explain every step.
